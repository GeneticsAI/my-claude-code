# 围场 Paddock 🏁

给跑车车友的活动组织 App：约跑、实时位置共享、GPS 圈速计时、车队对讲，再加上动态、关注、点赞评论这些基本的社交功能。

手机浏览器打开就能用，也可以「添加到主屏幕」当 App 用（PWA）；后端是一个 Node.js 进程 + SQLite 文件，部署简单。

## 功能

**活动组织**
- 发起活动：赛道日 / 山路巡航 / 车友聚会 / 自驾长途，在地图上点选集合点，可设人数上限
- 报名、退出、成员列表；活动卡片显示「实况中 N 人」
- 每个活动自带群聊

**实况地图**（活动成员可见）
- 所有共享位置的成员实时显示在地图上：航向箭头、昵称、实时车速、行驶尾迹，位置在两次 GPS 更新之间平滑移动
- 离线成员变灰；正在对讲的成员外圈闪动
- 底图可切换高德地图 / 高德卫星 / OpenStreetMap / Esri 卫星；GPS 的 WGS-84 坐标会自动纠偏到高德的 GCJ-02，不会出现「车开在河里」
- 「模拟驾驶」：没有车也能沿赛道自动跑，用于体验和测试

**专业计时与遥测**
- GPS 圈速计时：检测轨迹与起终点线的相交，并按交点位置插值穿线时刻，普通手机 1Hz 的 GPS 也能计到约 0.1 秒级
- 分段计时（S1/S2/S3…），分段格按 F1 惯例着色：紫色 = 全场最快，绿色 = 个人最佳
- HUD：车速、本圈用时、与个人最佳的实时差值 Δ、上圈、最佳、G 值球（纵向/横向加速度）
- 实时排行榜：最佳圈、与 P1 的差距、上一圈、圈数、每位车手的实时车速 / 当前圈 / Δ
- 圈速分析页：速度曲线与时间差曲线（可对比全场最快或个人最佳，在曲线上滑动，地图同步标出位置）、分段对比表、理论最佳圈、按速度着色的行驶轨迹
- 断网不丢圈：完成的圈先存在手机本地，重新连上后自动补传（服务器端幂等去重）

**车队对讲**
- 按住说话（电脑上也可以按住空格键），松开结束，有对讲机式提示音
- 16kHz 语音，端到端延迟约 0.2–0.3 秒（视网络而定）；多人可以同时说话；可一键静音收听
- 屏幕上方显示谁在讲话

**组织者工具**
- 在地图上横跨赛道点两下，即可设置起终点线和分段线，修改后实时同步给所有在线车友
- 一键在地图中心生成演示赛道

**社交**
- 动态：文字、图片、分享圈速成绩卡、分享活动
- 点赞、评论、关注 / 粉丝、通知（被赞、被评论、被关注、有人报名你的活动）
- 个人主页：座驾、简介、各活动的个人最佳圈；可换头像和车队颜色（用于地图标记和排行榜）
- 搜索车友、车型、活动

## 快速体验

需要 [Node.js](https://nodejs.org) **22.13 或更高**（推荐 24 LTS）。

```bash
cd paddock
npm install
npm run demo
```

打开 http://localhost:3000 ，用 **demo / paddock123** 登录。演示模式会写入一批车友、动态和活动，并让 6 位模拟车手在「周六晨练 · 赛道日（演示）」里实时跑圈、聊天：

1. 「活动」→ 进入演示赛道日 →「进入实况」，可以看到车手们在跑、排行榜在变
2. 点「开始共享位置」→「模拟驾驶」，自己也下场跑几圈，看 HUD 和实时 Δ
3. 再开一个浏览器（或无痕窗口）用 `linyu / paddock123` 登录同一个活动，按住右下角按钮试试对讲
4. 在活动详情页的排行榜点任意一行，进入圈速分析

macOS 上也可以直接双击 `start-demo.command`。

演示数据放在 `data-demo/`，每次 `npm run demo` 都会重建。

## 正式运行

```bash
npm start            # 数据保存在 ./data（SQLite 文件 + 上传的图片）
```

环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_DIR` | `./data` | 数据库和上传图片的目录（备份这个目录即可） |
| `TLS_CERT` / `TLS_KEY` | 无 | 证书路径，提供后以 HTTPS 启动 |

## 在手机上使用

浏览器只允许 **HTTPS** 页面使用定位和麦克风（电脑本机的 `localhost` 例外），所以手机要通过 HTTPS 访问：

- **临时测试（最简单）**：用内网穿透生成一个 HTTPS 链接，例如
  `cloudflared tunnel --url http://localhost:3000`，把输出的 `https://…trycloudflare.com` 发给车友即可。
- **长期使用**：部署到云服务器，前面放一个自动申请证书的反向代理，例如 Caddy：
  ```
  paddock.你的域名.com {
      reverse_proxy localhost:3000
  }
  ```
  WebSocket 会被自动转发，不需要额外配置。（中国大陆服务器使用域名需要先备案。）
- **局域网自签证书**：`openssl req -x509 -newkey rsa:2048 -nodes -days 365 -keyout key.pem -out cert.pem -subj "/CN=paddock"`，再用 `TLS_CERT=cert.pem TLS_KEY=key.pem npm start` 启动；手机需要手动信任这个证书，比较麻烦。

装到主屏幕：iPhone 用 Safari 打开 → 分享 →「添加到主屏幕」；安卓用 Chrome 打开 → 菜单 →「安装应用」。

车上使用建议：手机固定在支架上并接上电源。共享位置期间 App 会自动保持屏幕常亮，**不要锁屏或切到后台**，否则浏览器会暂停定位（见下方「已知限制」）。

## ⚠️ 安全

- 圈速计时只应在**封闭赛道**使用。公共道路上请遵守交通法规，巡航活动的位置共享只用于车队互相照应。
- 开车时不要操作手机。对讲建议由副驾操作，或者用蓝牙按键：App 把**空格键**当作对讲键，可以配合能发送空格键的蓝牙遥控器 / 按键使用。

## 隐私

- 只有你主动点「开始共享位置」后才会发送位置，并且只发给同一活动的成员；服务器**不保存位置历史**，只在内存里保留每人最后一个位置，不写入数据库。
- 完成的计时圈（包括行驶轨迹）会保存，用于排行榜和圈速分析，登录用户都能查看。
- 密码用 scrypt 加盐哈希存储；登录凭证在数据库里也只存哈希。

## 计时原理

```
GPS 点 A（t=12.0s）────────────╳──────────► GPS 点 B（t=13.0s）
                          起终点线
         交点位于 A→B 的 62% 处  ⇒  穿线时刻 = 12.0 + 0.62 × 1.0 = 12.62s
```

- 第一次穿越起终点线确定行驶方向，之后反向穿越（比如从维修区倒着开过线）会被忽略；20 秒内重复穿线视为抖动。
- 分段线必须按顺序经过，漏掉某条分段线的圈只记总圈速、不记分段。
- 实时 Δ：把本圈到目前为止跑过的距离，在最佳圈的轨迹上查出同一距离处用了多久，两者相减。
- G 值由 GPS 推算：纵向 = 速度变化率，横向 = 车速 × 航向角速度，做了平滑处理。

计时、坐标转换、模拟驾驶的代码在 `public/js/shared/`，浏览器、服务器、测试共用同一份。

## 项目结构

```
paddock/
├── server/
│   ├── index.js        启动入口（npm start）
│   ├── app.js          HTTP(S) 服务：静态资源、REST、WebSocket、安全响应头
│   ├── api.js          REST 接口（账号、动态、关注、活动、圈速、通知、搜索）
│   ├── realtime.js     WebSocket 实况房间：位置、圈速、群聊、对讲转发
│   ├── store.js        SQLite 数据层（Node 内置 node:sqlite，无需安装数据库）
│   ├── validate.js     输入校验
│   └── http.js         路由与静态文件
├── public/             前端（原生 ES 模块，无需构建）
│   ├── js/shared/      计时、地理计算、μ-law 编解码、模拟赛道（前后端共用）
│   ├── js/live/        地图、车辆标记、WebSocket、GPS、对讲
│   ├── js/views/       各个页面
│   ├── sw.js           离线缓存
│   └── manifest.webmanifest
├── scripts/
│   ├── demo.js         一键演示
│   ├── simulate.js     给任意服务器派模拟车手（联调 / 压测）
│   └── bots.js         模拟车手（走与 App 相同的协议）
└── test/               单元测试 + 接口 / 实时通道集成测试
```

实时协议见 `server/realtime.js` 文件头的注释。

## 已知限制与下一步

- **后台定位**：网页在锁屏或切到后台后无法继续定位。想要锁屏也能共享位置，需要打包成原生 App（例如用 Capacitor 包装现有前端，再加后台定位插件），现有代码基本可以直接复用。
- **计时精度**：手机 GPS 一般 1Hz、精度 3–5 米，适合车友之间娱乐比较，不能替代官方计时。可以接入 10/25Hz 的外置 GPS（如 RaceBox）来提高精度，计时代码不用改。
- **对讲规模**：语音经服务器转发，单台服务器适合几十人同场。规模更大时可以换成 WebRTC 媒体服务器（如 LiveKit）。
- **地图服务**：高德瓦片目前直接引用，商用前需要在高德开放平台申请 Key 并遵守其条款；OpenStreetMap 官方瓦片不适合大流量使用。
- **单机架构**：一个 Node 进程 + SQLite，适合车友会规模；用户多了需要把实时通道拆出来，并用 Redis 在多台服务器之间广播。
- 还没有：私信、内容举报与审核、找回密码、推送通知。
